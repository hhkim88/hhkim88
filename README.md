# 오타교정 키보드 (TypoFix Keyboard)

내가 자주 내는 오타를 스스로 학습해서 고쳐주는 안드로이드 커스텀 한글 키보드(IME)입니다.

## 아이디어

사람들은 오타를 치고 → 지우고 → 다시 쳐서 완성한 문장을 보냅니다. 이 "썼다 지웠다" 패턴 자체가
**오타 → 정답** 학습 데이터입니다. 이 앱은 시스템 키보드를 대체하는 커스텀 키보드로 동작하면서,
한 단어를 완성하는 동안의 편집 이력을 관찰해 이 패턴을 기기 내부에만 저장하고, 같은 오타가
충분히 반복되면 다음부터는 자동으로 고쳐줍니다. **모든 데이터는 기기 로컬 DB에만 저장되며 외부로
전송되지 않습니다.**

## 모듈 구조

```
core/   순수 Kotlin/JVM 모듈 (Android 의존성 없음) — 핵심 로직 + 단위 테스트
app/    Android 앱 — Room DB, 커스텀 키보드 UI, IME 서비스, 관리 화면
```

`core` 모듈을 Android 코드와 분리한 이유: 이 프로젝트에서 가장 까다롭고 정확성이 중요한 부분
(한글 자모 조합/분해, 오타 패턴 감지, 교정 신뢰도 로직)을 Android SDK 없이도 빌드·테스트할 수
있게 하기 위함입니다. 실제로 이 저장소를 만든 개발 환경에는 Android SDK가 없어서 `app` 모듈은
빌드해볼 수 없었지만, `core` 모듈은 `./gradlew :core:test`로 **29개 단위 테스트 전부 통과**를
확인했습니다.

### core 모듈

- **`HangulComposer`** — 표준 두벌식 자모 조합기. 자음/모음 키 입력을 실제 한글 음절로 조합하고,
  복합모음(ㅘㅙㅚㅝㅞㅟㅢ), 복합종성(ㄳㄵㄶㄺㄻㄼㄽㄾㄿㅀㅄ), 받침 이동("가"+"ㅏ" → "가"+"나")
  등 표준 규칙을 구현합니다. 백스페이스는 현재 조합 중인 음절은 자모 단위로 분해하고, 이미 확정된
  음절은 통째로 지우는 방식으로 단순화했습니다 (알려진 제약사항, 아래 참고).
- **`WordAttemptTracker`** — 한 단어를 입력하는 동안 문자열 길이가 늘었다 줄었다 하는 패턴을
  관찰해서 "이전에 타이핑했다가 지운 값(peak)"과 "최종적으로 확정한 값"을 구분해 냅니다. 이게
  바로 오타 감지의 핵심입니다.
- **`CorrectionStore` / `CorrectionEngine`** — 관찰된 (오타, 정답) 쌍을 저장하고, 같은 오타가
  일정 횟수(기본 2회) 이상 반복 관찰되면 자동교정을 제안합니다. 오타가 다른 정답으로 정정되면
  신뢰도(count)가 리셋되어 사용자의 최신 습관을 따라갑니다.
- **`KeyboardAdjacency` / `WeightedEditDistance` / `Dictionary` / `DictionarySuggester`** — 개인
  학습 이력이 전혀 없는, *처음 보는* 오타를 잡기 위한 두 번째 신호입니다. 완성한 단어가 사전에
  없으면, 두벌식 키 배치상 가까운 자모일수록 편집거리 비용을 낮게 매겨서 "가장 가까운 사전 단어"를
  찾습니다. 그 최선의 후보가 차선 후보보다 뚜렷하게 가까울 때만("그 타이핑으로 연결되는 실제 단어가
  사실상 하나뿐일 때만") 제안하고, 여러 단어가 비슷하게 가까우면 모호하다고 보고 아무것도 제안하지
  않습니다. 개인 기억 기반 자동교정과 달리 이 신호는 **조용히 자동 적용되지 않고 항상 눈에 보이는
  제안으로만** 뜨며, 사용자가 직접 수락(`CorrectionEngine.confirmSuggestion`)해야 그 단어가 개인
  사전에 즉시 신뢰도 있게 등록됩니다.

### app 모듈

- **`data/`** — Room 기반 로컬 DB. `RoomCorrectionStore`가 `core.CorrectionStore`를 구현하며,
  타이핑 중 매 키 입력마다 동기적으로 조회해야 하므로 메모리 캐시를 유지하고 실제 DB 쓰기는
  백그라운드 코루틴으로 처리합니다.
- **`ime/`** — `TypoKeyboardService`(`InputMethodService`)가 전체 흐름을 조립합니다: 키 입력을
  `HangulComposer`로 조합 → `WordAttemptTracker`로 관찰 → 단어 경계(스페이스/줄바꿈/문장부호/전송)
  에서 학습 기록 + 자동교정 적용. `KeyboardView`는 XML이 아닌 코드로 직접 그리는 완전한 커스텀
  키보드 뷰(두벌식 자판 + 기호 자판)입니다. 자동교정이 적용되면 키보드 위쪽 상태 바에
  "오타 → 정답" 힌트가 뜨고, 탭하면 되돌리면서 그 학습을 취소합니다. 같은 상태 바 오른쪽에는
  엄지가 바로 닿는 위치에 **자동교정 ON/OFF 토글**이 항상 떠 있어서, 학습된 오타 목록을
  건드리지 않고도 일시적으로 자동교정만 끌 수 있습니다(꺼도 학습은 계속됩니다). 개인 기억에는
  없지만 사전 기반으로 "이거 오타 아니야?"라고 제안할 때는 같은 자리에 **다른 색(주황)**으로
  "오타 → 제안? (탭하여 적용)"이 뜨며, 조용히 바로 고쳐지는 자동교정과 구분됩니다.
- **`assets/common_words_ko.txt`** — `DictionarySuggester`가 참고하는 한국어 단어 씨앗 목록.
  손으로 큐레이션한 예시 수준(수백 개)이라 실사용 전에 국립국어원 어휘 목록이나
  hunspell-dict-ko 같은 오픈소스 빈도 사전으로 교체/확장하는 것을 권장합니다 (이 개발 환경은
  인터넷에서 사전을 내려받을 수 없었습니다). `#`으로 시작하는 줄은 주석으로 무시됩니다.
- **`ui/`** — `MainActivity`(키보드 활성화 안내), `CorrectionsActivity`(학습된 오타 목록을 보고
  켜고 끄고 삭제하는 관리 화면).

## 빌드 / 실행 방법

이 환경(클라우드 세션)에는 Android SDK가 없어서 `app` 모듈은 여기서 빌드하지 못했습니다.
Android Studio(Koala 이상)에서 이 저장소를 열면 정상적으로 Gradle sync가 진행되고 빌드됩니다.

```bash
# core 모듈 로직 검증 (SDK 불필요, 어디서든 가능)
./gradlew :core:test

# 전체 앱 빌드 (Android SDK 필요 — Android Studio 또는 SDK가 설치된 환경)
./gradlew :app:assembleDebug
```

설치 후:
1. 앱 실행 → "키보드 설정 열기"로 시스템 설정에서 '오타교정 키보드'를 켠다.
2. 아무 텍스트창에서 키보드 전환 버튼으로 이 키보드를 선택한다.
3. 평소처럼 쓰다가 오타를 지우고 다시 써서 보내면, 그 패턴이 조금씩 쌓인다.
4. 앱의 "학습된 오타 보기"에서 쌓인 오타 목록을 확인/관리한다.

## 알려진 제약 사항 (v1)

- 백스페이스가 이미 확정된 음절까지 들어가면 자모 단위가 아니라 음절 단위로 지워집니다(단순화).
- 두벌식 자판만 지원합니다 (천지인 등 다른 배열 미지원).
- 오타 학습은 "한 단어 안에서의 자기 수정" 패턴만 봅니다. 여러 단어에 걸친 수정이나 문장
  전체를 지우고 다시 쓰는 경우는 반영되지 않습니다.
- 자동교정 되돌리기/제안 적용은 커밋 직후 커서가 그대로 있다는 가정하에 동작합니다.
- 사전 기반 제안은 내장된 씨앗 단어 목록 크기만큼만 똑똑합니다 — 목록에 없는 고유명사·신조어·
  줄임말은 실제로는 오타가 아니어도 사전에 없다는 이유만으로 제안이 뜰 수 있습니다(단, 조용히
  자동 적용되진 않고 항상 사용자가 직접 눌러야 반영됩니다). 또한 사전 전체를 단어마다 순회하는
  방식이라(`DictionarySuggester`), 사전을 수만 단어 이상으로 키우면 사전 길이 버킷팅이나 BK-tree
  같은 인덱싱이 필요합니다.
